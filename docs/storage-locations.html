Storage locations

A BackupStorageLocation is an S3-compatible bucket that holds backups. planb checks it, writes to it, deletes from it and imports what it finds there.

Example#

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: BackupStorageLocation
metadata:
  name: default
  namespace: db
spec:
  s3:
    endpoint: s3.eu-central-1.amazonaws.com
    region: eu-central-1
    bucket: my-backups
    prefix: planb
    credentials:
      name: backup-bucket          # Secret in the same namespace
      accessKeyIdKey: accessKey    # default
      secretAccessKeyKey: secretKey  # default
  accessMode: ReadWrite            # or ReadOnly
  syncPeriod: 1m                   # 0s disables sync

Backups refer to a location by name (spec.storageLocation), so each namespace that has Backups needs at least one location. Several locations can share a bucket if their prefixes differ.

Connecting to S3#

FieldMeaning
endpointhost[:port] without a scheme, for example s3.amazonaws.com, minio.minio.svc:9000 or <account>.r2.cloudflarestorage.com.
bucketBucket name. It must already exist; planb never creates buckets.
prefixOptional folder. Backups go to <prefix>/backups/<name>/.
regionBucket region. Needed by AWS for buckets outside us-east-1.
insecurePlain HTTP instead of HTTPS. Only for in-cluster test endpoints.
skipTLSVerifyAccept any TLS certificate, for self-signed MinIO or Ceph. Prefer a proper CA.
credentialsSecret with the access key. When omitted, the AWS credential chain is used: environment variables, then the instance or pod IAM role.

The access key needs s3:ListBucket, s3:GetObject, s3:PutObject and s3:DeleteObject on the bucket, plus s3:AbortMultipartUpload to clean up failed uploads. A ReadOnly location only needs list and get.

Validation#

Every syncPeriod (default 1 minute, at least 10 seconds) the operator checks that the bucket exists and is reachable, and sets the phase:

kubectl get bsl -A
NAMESPACE   NAME      PHASE       ENDPOINT                        BUCKET       ACCESS      LAST VALIDATED
db          default   Available   s3.eu-central-1.amazonaws.com   my-backups   ReadWrite   12s

The phase is informational. Backups and restores still start while a location is Unavailable, and the agent's own retries ride out short outages. If the bucket stays unreachable, they fail with the S3 error. The reason for Unavailable is in status.message and in an Unavailable event.

Access modes#

  • ReadWrite (default): backups, restores, TTL garbage collection and data deletion.
  • ReadOnly: restores only. New Backups fail with StorageLocationReadOnly, expired backups are not deleted, and deleting a Backup keeps its data. Use it to attach another cluster's backups, for example in a disaster recovery drill, without any risk of changing them.

Sync from storage#

After each successful check, the operator lists <prefix>/backups/ and creates a Backup for every completed backup it finds that isn't in the namespace yet. That means it has a planb-backup.json with phase Completed. Imported Backups:

  • keep their name, labels, spec and status from the metadata file;
  • point at the importing location (spec.storageLocation and the planb.sina-devel.github.io/storage-location label);
  • carry the annotation planb.sina-devel.github.io/synced-from-storage: "true";
  • are skipped if already expired, unless the location is ReadOnly.

Sync never overwrites a Backup that was created in the cluster. Set syncPeriod: 0s to switch it off. Validation then runs every minute.

Deleting an imported Backup deletes the data

On a ReadWrite location, an imported Backup is a normal Backup: deleting it, or letting its TTL expire, removes the data from the bucket. That affects every cluster sharing the bucket. Attach shared buckets as ReadOnly unless this cluster should own the backups.

Deleting a location#

Deleting a BackupStorageLocation never deletes data. While a location is missing or being deleted, deleting its Backups keeps their data too.
