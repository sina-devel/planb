Troubleshooting

Where to look when something goes wrong, and the fixes for the errors people hit most.

Where to look#

  1. Status: kubectl get backups,restores -n db, then kubectl get backup NAME -n db -o jsonpath='{.status.message}'. The message holds the agent's error.
  2. Events: kubectl describe backup NAME -n db shows each step: job created, completed, failed, expired, deleted.
  3. Agent logs: kubectl logs -n db job/planb-backup-NAME (or planb-restore-NAME). Jobs are kept for manager.jobTTLSeconds (a day by default). The UI shows the same logs.
  4. Operator logs: kubectl logs -n planb-system deploy/planb. Set manager.logLevel=debug for more.

Common problems#

Storage location stays Unavailable#

  • bucket "x" does not exist: create the bucket; planb never creates buckets.
  • The Access Key Id you provided does not exist or SignatureDoesNotMatch: wrong key, or the wrong accessKeyIdKey/secretAccessKeyKey in the Secret reference.
  • http: server gave HTTP response to HTTPS client: the endpoint speaks plain HTTP; set insecure: true.
  • x509: certificate signed by unknown authority: a self-signed endpoint; use a trusted certificate or skipTLSVerify: true.
  • The authorization header is malformed; the region 'us-east-1' is wrong: set region.
  • dial tcp ... i/o timeout: a NetworkPolicy or firewall blocks the operator or the Jobs. Both need to reach the endpoint.

pg_dump: password authentication failed / no pg_hba.conf entry#

Check the credentials Secret and its usernameKey/passwordKey. The Job connects from the Pod network of the Backup's namespace, so pg_hba.conf must allow that CIDR. With sslMode: require or stricter, the server must offer TLS.

pg_dump: server version mismatch#

The client must be at least as new as the server. The image ships PostgreSQL 18 tools. For a newer server, build an agent image with a newer client and set spec.job.image.

pg_dump: permission denied for table ...#

The backup role must be able to read everything; see permissions. Exclude tables you can't read with extraArgs: [--exclude-table=NAME].

pg_restore: relation ... already exists#

The target database isn't empty. Restore with clean: true, or into a new name with databaseMapping.

"backup is a full pg_dumpall dump: databases/databaseMapping are not supported"#

The backup was taken without databases. Restore it whole into an empty server, or take per-database backups in future.

Backup failed: StorageLocationReadOnly#

The location has accessMode: ReadOnly. Use another location or change the mode.

Backup stuck in Deleting#

The finalizer is trying to delete the data and the bucket is unreachable or the key can't delete. The operator keeps retrying; the reason is in the events. To give up on the data, remove the finalizer:

kubectl patch backup NAME -n db --type=merge -p '{"metadata":{"finalizers":null}}'

Job OOMKilled#

Each concurrent multipart upload buffers one part, 64 MiB by default. Give the Job more memory with spec.job.resources, or lower PLANB_PART_SIZE_MB. Pruning very large buckets also needs memory for the key list.

Backups take long and the logs show "retrying after error"#

The provider throttles or the network is unstable. planb is riding it out; see Retries and reliability. If it keeps happening, lower the load (fewer parallel schedules) or raise spec.job.retry.maxBackoff.

Backups don't appear in a new cluster#

  • The location must use the same bucket and prefix as the cluster that wrote them.
  • Only completed backups with a planb-backup.json are imported. Expired ones are skipped unless the location is ReadOnly.
  • A Backup with the same name already exists in the namespace.
  • syncPeriod: 0s switches sync off.

Notifier is Failed#

kubectl describe notifier NAME shows the HTTP or SMTP error. Telegram often needs a proxy; see Proxies. Send a test after fixing it.
