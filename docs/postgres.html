PostgreSQL

Back up single databases as binary pg_dump archives or a whole server as SQL, then restore them in place, under new names or onto another server.

Two backup modes#

SpecToolStored asRestore
databases: [a, b]pg_dump --format=custompostgres/a.dump, postgres/b.dump: binary, compressedpg_restore; selective, renameable, with clean
no databasespg_dumpallpostgres/all.sql.gz: plain SQL, gzippedpsql; the whole file, into an empty server
includeGlobals: truepg_dumpall --globals-onlypostgres/globals.sql.gz: roles and tablespacesreplayed first with restoreGlobals

Use per-database backups unless you really need the whole server. The custom format is compressed, can restore single databases under another name, and can drop existing objects first. A pg_dumpall backup is plain SQL that can only be replayed whole.

Each dump is a consistent snapshot of its database: pg_dump runs in one repeatable-read transaction and doesn't block normal reads and writes.

Backup#

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: Backup
metadata:
  name: app-2026-10-29
  namespace: db
spec:
  storageLocation: default
  ttl: 720h                       # default: --default-backup-ttl (720h)
  postgres:
    host: postgres.db.svc         # Service, hostname or IP
    port: 5432                    # default
    sslMode: prefer               # disable | allow | prefer | require | verify-ca | verify-full
    credentials:
      name: postgres-credentials
      usernameKey: username       # default
      passwordKey: password       # default
    databases: [app, billing]
    includeGlobals: true
    extraArgs: [--exclude-table-data=audit_log]
  job:
    resources: { requests: { cpu: 500m, memory: 256Mi } }
    activeDeadlineSeconds: 7200

Extra arguments#

extraArgs are appended to pg_dump, or to pg_dumpall for a full-server backup. Useful ones:

  • --exclude-table-data=PATTERN: keep the table definition but skip its rows.
  • --schema=NAME / --exclude-schema=NAME: limit the dump to some schemas.
  • --no-owner, --no-privileges: make the dump portable between servers with different roles.
  • --compress=zstd:5: a different compression method or level (PostgreSQL 16+ client).

Permissions#

The backup user needs CONNECT on each database and SELECT on everything in it, usually by being the owner or a member of pg_read_all_data (PostgreSQL 14+). includeGlobals and full-server backups read pg_authid for role passwords, so they need a superuser. On managed services that hide passwords, add extraArgs: [--no-role-passwords].

Client version#

The image ships the PostgreSQL 18 client tools. pg_dump can dump any server from 9.2 on, and dumps restore into the same or a newer server. To use a different client, set spec.job.image on the Backup, or manager.agentImage in the chart, to an image that contains both the planb binary and that client.

Restore#

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: Restore
metadata:
  name: app-into-staging
  namespace: db
spec:
  backupName: app-2026-10-29
  postgres:
    target:                       # default: the server the backup came from
      host: postgres-staging.db.svc
      credentials: { name: staging-credentials }
    databases: [app]              # default: every database in the backup
    databaseMapping: { app: app_copy }
    createDatabase: true          # default
    clean: false
    restoreGlobals: false
    extraArgs: [--no-owner]
OptionEffect
targetRestore to another server. sslMode and port default as in a Backup.
databasesRestore only these. A name that isn't in the backup fails the Restore.
databaseMapping{source: target}: restore a database under a different name.
createDatabaseCreate each target database if it doesn't exist (default true).
cleanpg_restore --clean --if-exists: drop each object before recreating it. Needed to restore over an existing database.
restoreGlobalsReplay globals.sql.gz (roles, tablespaces) before the databases. Roles that already exist produce errors in the log, which are ignored.
extraArgsAppended to pg_restore or psql, e.g. --no-owner, --jobs=4, --section=data.

pg_restore runs with --exit-on-error, so the first error stops the Restore and appears in its status. Each database is restored in turn; databases restored before an error are left as they are.

Common patterns#

  • Check a backup without touching production: restore with databaseMapping: {app: app_verify}, run your checks, then drop app_verify.
  • Roll a database back: restore into the same name with clean: true. Stop writers first; clean doesn't remove objects that were created after the backup.
  • Refresh staging from production: restore with a target server and extraArgs: [--no-owner, --no-privileges] when the roles differ.

Full-server restores#

A pg_dumpall backup is replayed with psql as it is: it creates roles and databases and then loads them. Restore it into an empty server, for example a fresh one in a recovery cluster. databases and databaseMapping are rejected for this kind of backup. Replaying into a server that already has the same databases produces "already exists" errors, which psql reports but which don't stop it.
