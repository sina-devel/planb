Getting started

Install planb, point it at a bucket, back up a PostgreSQL database and restore it under a new name. This takes about ten minutes.

Prerequisites#

  • A Kubernetes cluster, version 1.30 or newer. k3s, kind, EKS, GKE and AKS all work.
  • kubectl and Helm 3 or newer.
  • An S3-compatible bucket for the backups, plus an access key that can list, read, write and delete objects in it. AWS S3, MinIO, Ceph RGW, Cloudflare R2, Wasabi and other S3-compatible stores work.
  • Something to back up: a PostgreSQL server reachable from the cluster, or another S3 bucket.

If you only want to try planb, skip the bucket and the database: Try it locally deploys throwaway ones into the cluster.

1. Install the operator#

The Helm chart is in the repository. It installs the CRDs, the operator and, optionally, the web UI.

git clone https://github.com/sina-devel/planb && cd planb
helm upgrade --install planb charts/planb -n planb-system --create-namespace

Check that the operator is running:

kubectl get pods -n planb-system
kubectl get crd | grep planb.sina-devel.github.io

To add the web UI, see Web UI. For every chart setting, see Installation and Helm.

2. Store the credentials#

planb reads credentials only from Secrets in the namespace of the resources that use them. In this guide that namespace is db.

kubectl create namespace db

# S3 access key for the backup bucket
kubectl create secret generic backup-bucket -n db \
  --from-literal=accessKey=AKIA... --from-literal=secretKey=...

# PostgreSQL user that may run pg_dump on the databases you back up
kubectl create secret generic postgres-credentials -n db \
  --from-literal=username=postgres --from-literal=password=...

3. Create a storage location#

A BackupStorageLocation is the bucket backups are written to. planb checks every minute that it can reach it.

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: BackupStorageLocation
metadata:
  name: default
  namespace: db
spec:
  s3:
    endpoint: s3.eu-central-1.amazonaws.com   # host[:port], no scheme
    region: eu-central-1
    bucket: my-backups
    prefix: planb                             # optional folder inside the bucket
    credentials: { name: backup-bucket }
kubectl apply -f storage-location.yaml
kubectl get bsl -n db        # PHASE should become Available

If the phase is Unavailable, kubectl describe bsl default -n db shows why. Usually it's a wrong endpoint, region or key.

4. Back up a database#

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: Backup
metadata:
  name: app-manual-1
  namespace: db
spec:
  storageLocation: default
  postgres:
    host: postgres.db.svc
    credentials: { name: postgres-credentials }
    databases: [app]          # one pg_dump file per database
    includeGlobals: true      # also roles and tablespaces
kubectl apply -f backup.yaml
kubectl get backups -n db -w

The Backup moves from New to InProgress to Completed. The work runs in a Job called planb-backup-app-manual-1, whose logs show each step:

kubectl logs -n db job/planb-backup-app-manual-1

The data now sits in the bucket under planb/backups/app-manual-1/.

5. Restore it#

Restore the database next to the original, under a new name, so you can compare the two:

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: Restore
metadata:
  name: app-restore-test
  namespace: db
spec:
  backupName: app-manual-1
  postgres:
    databaseMapping: { app: app_restored }
kubectl apply -f restore.yaml
kubectl get restores -n db -w

createDatabase is on by default, so planb creates app_restored before restoring into it.

6. Back up every night#

apiVersion: planb.sina-devel.github.io/v1alpha1
kind: Schedule
metadata:
  name: app-nightly
  namespace: db
spec:
  schedule: "CRON_TZ=Europe/Berlin 0 3 * * *"
  keepLast: 7                # keep a week of backups
  template:                  # a Backup spec
    storageLocation: default
    ttl: 720h
    postgres:
      host: postgres.db.svc
      credentials: { name: postgres-credentials }
      databases: [app]

To hear about failures, add a Notifier.

Try it locally#

hack/demo/ deploys a throwaway PostgreSQL with a seeded app database (1,000 rows), an S3 endpoint served by rclone serve s3, and a storage location pointing at it. Everything lives in the planb-demo namespace:

kubectl apply -f hack/demo/infra.yaml
kubectl wait -n planb-demo --for=condition=Available deploy --all
kubectl get bsl -n planb-demo -w              # wait for Available
kubectl apply -f hack/demo/backup.yaml        # a database and a bucket backup
kubectl get backups -n planb-demo -w
kubectl apply -f hack/demo/restore.yaml       # restore both next to the originals

kubectl exec -n planb-demo deploy/postgres -- \
  psql -U postgres -d app_restored -c 'select count(*) from customers'

kubectl delete ns planb-demo                  # clean up
No access to Docker Hub?

Push postgres:18-alpine and rclone/rclone:1.75 to a registry the cluster can reach, then rewrite the images on the fly: sed 's#image: #image: localhost:5000/#' hack/demo/infra.yaml | kubectl apply -f -.
