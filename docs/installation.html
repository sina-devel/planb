Installation and Helm

Every setting of the Helm chart and the operator, and how to run planb with your own images, in one namespace or behind a proxy.

Install#

git clone https://github.com/sina-devel/planb && cd planb
helm upgrade --install planb charts/planb -n planb-system --create-namespace -f my-values.yaml

The chart installs the five CRDs from charts/planb/crds/, the operator Deployment with its ServiceAccount and ClusterRole and, when enabled, the UI.

Images#

Multi-arch images (linux/amd64, linux/arm64) are published to ghcr.io/sina-devel/planb:

TagBuilt from
X.Y.Z, X.Yrelease tags vX.Y.Z. The chart's appVersion is the default tag.
mainthe latest commit on main
sha-<commit>every commit

The same image runs the operator, the agent in each Job, and the UI. It's based on postgres:18-alpine for the client tools and runs as UID 65532.

To build your own: make docker-build docker-push IMG=registry.example.com/planb:dev, then --set image.repository=registry.example.com/planb --set image.tag=dev.

Operator flags#

The chart sets these from the values above. They matter only if you run the binary yourself (planb manager, or make run during development).

FlagEnvironmentDefault
--watch-namespaceWATCH_NAMESPACEall
--agent-imagePLANB_AGENT_IMAGEset by the chart
--agent-image-pull-policyPLANB_AGENT_IMAGE_PULL_POLICYIfNotPresent
--default-backup-ttl720h
--job-ttl-seconds86400
--cluster-namePLANB_CLUSTER_NAME
--leader-electfalse
--metrics-bind-address:8080
--health-probe-bind-address:8081

The UI (planb ui) takes --bind-address (PLANB_UI_ADDR, default :8090), --namespace (PLANB_UI_NAMESPACE) and --read-only (PLANB_UI_READ_ONLY). The agent reads PLANB_PART_SIZE_MB for the multipart chunk size.

Single-namespace install#

helm upgrade --install planb charts/planb -n db --set manager.watchNamespace=db --set ui.namespace=db

The operator then only sees resources in db. Its RBAC is still a ClusterRole, because the CRDs are cluster-scoped.

Uninstall#

helm uninstall planb -n planb-system

Helm keeps the CRDs, so your Backup objects survive an uninstall and reinstall. Removing everything:

Deleting the CRDs deletes every planb object

If the operator is still running, the Backups' finalizers delete their data from the buckets. To keep the data, uninstall the operator first and remove the finalizers, or annotate every Backup with planb.sina-devel.github.io/retain-data=true before deleting anything.

kubectl annotate backups --all -A planb.sina-devel.github.io/retain-data=true
helm uninstall planb -n planb-system
kubectl get crd -o name | grep planb.sina-devel.github.io | xargs kubectl delete
