Upgrading

How to upgrade planb, and what changed between versions, including the API group move in 0.3.0.

Upgrade procedure#

Helm installs CRDs on the first install but never upgrades them. Apply the new CRDs first, then upgrade the release:

git pull   # or check out the release tag
kubectl apply --server-side -f charts/planb/crds
helm upgrade planb charts/planb -n planb-system --reuse-values

Running backups and restores aren't interrupted: they run in their own Jobs, and the new operator picks up their results.

0.3.0#

Changes#

  • API group renamed from planb.io to planb.sina-devel.github.io, including every label, annotation and finalizer key. planb doesn't own planb.io, and a group name should be a domain you control, so that no other project's CRDs can collide with it.
  • Prune on bucket restore: spec.bucket.prune and status.deletedItems (details).
  • Retries with backoff: spec.job.retry, resumable downloads and listings, longer S3 request backoff, PostgreSQL-aware retry rules (details).
  • Bucket backups of the storage location's own bucket leave planb's backups out.
  • An upload failure during a dump now reports the S3 error instead of "pg_dump: signal: killed".

Migrating from planb.io#

The new CRDs are separate resources. The old objects aren't converted, and the new operator ignores them. Your backup data stays where it is, and the new version imports it through sync, because planb-backup.json doesn't depend on the group.

  1. Export what you created by hand, so you can re-apply it under the new group: 
    for k in backupstoragelocations schedules notifiers; do
  kubectl get $k.planb.io -A -o yaml > old-$k.yaml
done
  2. Stop the old operator and protect the data. Remove the finalizers so deleting the old objects can't delete any data: 
    kubectl scale deploy/planb -n planb-system --replicas=0
kubectl get backups.planb.io -A \
  -o jsonpath='{range .items[*]}{.metadata.namespace}{" "}{.metadata.name}{"\n"}{end}' |
  while read -r ns name; do
    kubectl patch backups.planb.io "$name" -n "$ns" --type=merge -p '{"metadata":{"finalizers":null}}'
  done
  3. Install 0.3.0 with the procedure above. This adds the new CRDs next to the old ones.
  4. Re-apply storage locations, schedules and notifiers, with apiVersion: planb.sina-devel.github.io/v1alpha1 and renamed label and annotation keys: 
    sed 's#planb\.io/#planb.sina-devel.github.io/#g' old-backupstoragelocations.yaml old-schedules.yaml old-notifiers.yaml \
  | grep -v -e 'resourceVersion:' -e 'uid:' -e 'creationTimestamp:' | kubectl apply -f -
    Within one syncPeriod, every completed backup reappears as a Backup under the new group.
  5. Remove the old CRDs when you're happy. Their objects no longer have finalizers, so nothing touches the data: 
    kubectl delete crd backups.planb.io restores.planb.io schedules.planb.io \
  backupstoragelocations.planb.io notifiers.planb.io
Label selectors

Notifier selectors and your own tooling that use planb.io/schedule or other planb.io/ keys need the new prefix.
